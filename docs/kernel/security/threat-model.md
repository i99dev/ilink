# Security limits

Primary boundaries are release update identity, local permission consent, browser isolation and vehicle safety. An archive digest binds mini-app consent to reviewed bytes; it does not prove authorship. Android install consent and package/certificate checks protect updates independently of mini-app scopes.

The application cannot guarantee safe behavior on compromised head-unit firmware or unsupported vehicle interfaces. A successful command reply does not prove physical movement. Current stationary gating allows an unknown speed reading; physical tests must use an identified safe, stationary target.

Optional media and model downloads contact public services when enabled. Imported content can be untrusted; local file and navigation checks, request restrictions, scope checks and owner revocation remain necessary. Native secondary surfaces provide no host JS bridge and restrict resources to the app's own bundle.

Legacy issuer-bound extension authority is not replaced by local owner consent. Missing or expired required authority remains a denial. See [legacy verification](../pubkey/README.md) and [current verification](../../offline-first/final-verification.md).
